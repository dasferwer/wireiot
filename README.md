# WireIoT

Телеметрия устройств через HTTP и MQTT с минутными агрегатами, поздними
исправлениями и обнаружением потери связи. PostgreSQL хранит исходные события,
агрегаты и историю изменения оконного правила; RabbitMQ уведомляет обработчик.

## Семантика времени и повторов

- Время события обязательно имеет часовой пояс. Допустимы события не старше суток
  и не дальше 30 секунд в будущем относительно приёма сервером.
- Окно — календарная минута UTC. Оно принимает исправления ещё 10 минут после
  окончания минуты. Решение об участии принимается при приёме события.
- Слишком позднее событие сохраняется, но не меняет агрегат. Окно становится
  финальным после дедлайна и обработки всех принятых для него событий.
- Ключ `(device,id)` обеспечивает дедупликацию. Другое значение или время под
  прежним ID отклоняется. Дубликат не обновляет признак связи с устройством.
- Агрегаты count/sum/min/max и отметка обработки фиксируются одной транзакцией.
  После сбоя незавершённое событие безопасно обрабатывается повторно.
- Правило: среднее окна не меньше порога устройства. Позднее исправление может
  включить или отозвать тревогу; каждый переход сохраняется с ревизией окна.
- Устройство считается пропавшим, когда с последнего нового принятого события
  прошло больше `timeout` секунд. Проверка выполняется при запросе списка устройств.

Стек: Python 3.11+, FastAPI, PostgreSQL 17, RabbitMQ, Eclipse Mosquitto,
paho-mqtt. `service.py` содержит временную семантику и агрегаты, `bridge.py` —
MQTT-мост, `worker.py` — обработчик, `api.py` — регистрацию и HTTP API.

## Запуск

```sh
docker compose up --build -d
curl -H 'X-API-Key: local-demo-key' http://localhost:8097/health
curl -X POST http://localhost:8097/devices \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"id":"sensor-1","threshold":70,"timeout":60}'
```

Сохраните `token` из ответа: в БД хранится только SHA-256 ключа устройства.
`POST /devices/sensor-1/events` принимает `id` (UUID), `happened_at` и `value`
с заголовком `X-Device-Key`. Значение — число от −1000 до 1000, до трёх знаков
после запятой. Пример тела:

```json
{"id":"00000000-0000-4000-8000-000000000001","happened_at":"2026-09-24T12:00:00Z","value":"72.500"}
```

Подставьте актуальное время. MQTT-топик — `telemetry/sensor-1`, QoS 1,
тело — `{"token":"ключ устройства","event":{...}}`. Мост подтверждает доставку
после фиксации в PostgreSQL. При временной ошибке БД переподключается без
подтверждения сообщения. Некорректные события отклоняет с записью в журнал.

Административные запросы требуют `X-API-Key`:

```sh
curl -H 'X-API-Key: local-demo-key' http://localhost:8097/devices
curl -H 'X-API-Key: local-demo-key' http://localhost:8097/devices/sensor-1/windows
curl -H 'X-API-Key: local-demo-key' http://localhost:8097/devices/sensor-1/alerts
```

Схема API: `/docs`. Порог и тайм-аут задаются при регистрации и далее не меняются.

## Эмулятор и проверки

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run python -m scripts.emulate
```

Эмулятор дожидается готовности подписчика MQTT, перемешивает 90 событий,
повторяет 15 из них и разрывает соединение издателя в середине передачи.
Затем сравнивает три потоковых окна с независимым пакетным расчётом и ждёт
обнаружения потери связи. Тесты используют временные схемы PostgreSQL и проверяют
поздние исправления, отзыв тревоги, плохие часы, закрытые окна и дубликаты.
CI запускает тесты и полный MQTT-сценарий с Mosquitto, RabbitMQ и PostgreSQL.

## Ограничения

Одна числовая метрика и одно правило на устройство, без прогнозирования отказов.
Обработка идёт по одному событию за транзакцию; высокую пропускную способность
этот стенд не заявляет. RabbitMQ ускоряет пробуждение, но источником состояния
служит БД. Мост имеет фиксированный MQTT client ID и запускается в одном экземпляре.
Нет ротации ключей, очистки истории, квот устройств и внешних уведомлений offline.

MQTT-брокер демонстрационный, без TLS и с anonymous-доступом на localhost.
Ключ в сообщении защищает приём сервисом, но не конфиденциальность MQTT-трафика.
Для реального развёртывания нужны TLS, учётные записи брокера и ACL по топикам.
QoS 1 допускает повторную доставку; дедупликация выполняется в PostgreSQL.
После суток повтор старого события отклоняется проверкой временного диапазона.

Порты доступны только на localhost. Остановка: `docker compose down`;
тома сохраняются. Документация: [paho-mqtt](https://eclipse.dev/paho/clients/python/docs/).
